JeePHP 2.7.0 Development Console

What's included
- A bottom-right Console tab on HTML pages in APP_ENV=local/development with APP_DEBUG=true.
- Captures uncaught PHP exceptions, fatal PHP errors, browser JavaScript errors, rejected promises, asset load errors, and console.error() messages.
- PHP error page includes message, source file and line, stack trace, and rule-based debugging suggestions.
- Possible N+1 query monitor warnings also appear inside the tab during local debug requests.
- Debug details and the panel are disabled in production mode.
- README and the JeePHP manual describe configuration, behavior, and production precautions.

Apply the source update
1. Back up your project and preserve your local .duck file and .git folder.
2. Extract the update ZIP into the JeePHP project folder and replace matching files.
3. Run composer dump-autoload if Composer does not detect the new Debug/DeveloperConsole.php class.
4. In .duck, use APP_ENV=local and APP_DEBUG=true to see the panel. APP_ENV=development is supported too.
5. Open an HTML page and click Console at the bottom-right. Trigger a test PHP or JavaScript error to review the message, location, and suggestions.
6. Before deployment, set APP_ENV=production and APP_DEBUG=false. Do not expose debug traces to public users.
7. In VS Code Source Control, inspect, stage, commit, and push the changes. Create/push a release tag only when ready to publish the new Composer version.

Limits
- Suggestions are rule-based hints; they do not edit files or guarantee a fix.
- JavaScript diagnostics appear in the panel running in that browser tab and are not sent to the server.
- Debug information can reveal source paths and details; use only in private development environments.
